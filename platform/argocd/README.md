# platform/argocd/

ArgoCD installation and GitOps configuration for the eel IEMS. Manages all 18 services across primary, mirror, and edge sites via ApplicationSets.

## Contents

| Path | Description |
|---|---|
| `install.yaml` | ArgoCD install manifest (pinned version) |
| `app-projects.yaml` | AppProject definitions per service group |
| `projects/` | Per-service AppProject overrides |
| `applicationsets/` | One ApplicationSet YAML per service (hand-authored or generated by `eel-appset-gen`) |
| `applicationsets/generated/` | Machine-generated ApplicationSets; committed by CI |
| `notifications.yaml` | Notification triggers (Slack, PagerDuty) |
| `rollouts/` | Argo Rollouts progressive delivery configs |

## Install ArgoCD

```bash
# Apply base install:
kubectl apply -n argocd -f platform/argocd/install.yaml

# Apply projects and ApplicationSets:
kubectl apply -n argocd -f platform/argocd/app-projects.yaml
kubectl apply -n argocd -f platform/argocd/applicationsets/
```

## ApplicationSet structure

Each `applicationsets/<svc>.yaml` fans one service out across sites using a matrix generator:

```yaml
generators:
  - matrix:
      generators:
        - list:
            elements: [{site: primary}, {site: mirror}]
        - git:
            repoURL: ...
            files: [{path: "services/<svc>/deploy/manifest.yaml"}]
```

The `generated/` subdirectory is updated by `eel-appset-gen gen` on every service manifest change.

## Sync policy

- Auto-sync is enabled for tier-1 platform components.
- Auto-sync is disabled for election-critical services during the election-day freeze window (enforced by `platform/election-day-mode/freeze-window-policy.yaml`).
- Self-heal is enabled cluster-wide; manual drift is corrected within 3 minutes.

## Notifications

`notifications.yaml` routes sync failures and health degradation to:
- Slack `#eel-ops` for warnings
- PagerDuty P1 for election-critical project failures

## Operator responsibilities

- Never edit generated ApplicationSets by hand; re-run `eel-appset-gen`.
- AppProjects restrict source repos and destination namespaces; do not widen them without an ADR.
- Argo Rollouts configs in `rollouts/` control canary and blue-green deployments.
