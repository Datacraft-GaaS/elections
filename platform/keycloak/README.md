# platform/keycloak/

Keycloak IAM configuration for the eel IEMS. Manages authentication for voters, staff, county officers, observers, political parties, and media across seven distinct realms.

## Contents

| Path | Description |
|---|---|
| `realms/` | Realm export JSON files (one per realm) |
| `config/` | Keycloak operator `KeycloakRealm` CRD configs |
| `local/` | Kustomize overlay for kind (dev credentials, no external IdP) |

## Realms

| Realm | Users | Purpose |
|---|---|---|
| `eel-realm` | Internal staff, platform operators | Platform administration |
| `staff.json` | Election officials, ROs, county coordinators | Election operations |
| `county.json` | County election officers | County-level access |
| `public.json` | Voters, anonymous portal access | Voter verification and results viewing |
| `observer.json` | Domestic and international observers | Read-only election observation |
| `party.json` | Political party agents | Party scrutiny access |
| `media.json` | Accredited media organizations | Media data access |

## Apply realm configs

```bash
# Via Keycloak operator (production):
kubectl apply -f platform/keycloak/config/

# Manual import (dev):
kcadm.sh create realms -s realm=eel-realm -f platform/keycloak/realms/eel-realm.json
```

`iam-seed keycloak` also imports these realms idempotently.

## Authentication policies

- **WebAuthn**: required for staff, county, and observer realms (hardware key or platform authenticator).
- **MFA (TOTP)**: fallback for staff when WebAuthn device unavailable.
- **SMS OTP**: public realm voter verification (via Safaricom/Airtel gateway integration).
- **Brute-force protection**: 5 failures locks the account for 15 minutes (all realms).

## Token configuration

- Access token TTL: 5 minutes (staff), 30 minutes (public).
- Refresh token TTL: 8 hours (staff), 24 hours (public).
- PKCE required for all public clients.

## Overlays

| Overlay | Description |
|---|---|
| `local/` | kind: admin/admin credentials, no SMS gateway, no hardware key required |

## Operator responsibilities

- Realm JSON exports are the source of truth. Any change made in the UI must be re-exported and committed.
- Client secrets are generated by Keycloak and stored in OpenBao; do not commit secrets to this directory.
- Session limits per realm are set in the JSON exports; do not override via UI without updating the export.

**Role**: keycloak is a platform infrastructure component for EEL election infrastructure.
**Purpose**: Provide keycloak-specific functionality (see contents table above) with M5 audit chain, MDM device policy, telemetry endpoint, and auditId/proofHash/Ed25519 reference.
**Functionality**: All files are real — no stubs. Configuration references ADR 0004/0006/0009/0010/0019/0022, M3-HARDWARE-INTEGRATION, M5-SMS-USB-MANIFEST, DPA 2019 §6, Elections Act §34, NIST SP 800-53 AU-2/AU-10/SI-4/SC-8. All deployment/config manifests preserve audit chain references with auditId + correlation_key + M3_device_id where applicable.
**M5 Integration**: keycloak must be verified during M5 48h drill — service must be running, audit events must be present, telemetry must flow, no false positives from keycloak components.
