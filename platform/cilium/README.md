# platform/cilium/

Cilium CNI, mesh, and network policy configuration for the eel IEMS. Provides eBPF-based networking, mutual TLS via SPIFFE SVIDs, and default-deny network policy.

## Contents

| File | Description |
|---|---|
| `values.yaml` | Helm values for the Cilium install (wireguard encryption, Hubble enabled, SPIRE integration) |
| `default-deny.yaml` | `CiliumNetworkPolicy` that denies all ingress/egress by default cluster-wide |
| `local/` | Kustomize overlay for kind (disables wireguard, reduces resource requests) |

## Install

```bash
# Helm install (production):
helm upgrade --install cilium cilium/cilium \
  --namespace kube-system \
  --version 1.15.x \
  -f platform/cilium/values.yaml

# Apply default-deny policy:
kubectl apply -f platform/cilium/default-deny.yaml

# Local dev (kind):
kubectl apply -k platform/cilium/local/
```

## Key configuration

- **WireGuard transparent encryption**: node-to-node traffic encrypted in-kernel. Enabled in `values.yaml` under `encryption.enabled: true`.
- **SPIRE integration**: Cilium reads SPIFFE SVIDs from the SPIRE agent socket to enforce identity-based policy.
- **Hubble observability**: flow logs exported to `platform/observability/` OTel Collector.
- **Default-deny**: `default-deny.yaml` is applied first. Services add explicit allow rules in their `deploy/` directories.

## Per-service network policies

Each service's Kustomize overlay (`services/<svc>/deploy/overlays/*/`) includes a `CiliumNetworkPolicy` generated by `eel-appset-gen`. These allow only the documented producer/consumer pairs from `manifest.yaml`.

## Overlays

| Overlay | Description |
|---|---|
| `local/` | kind dev: no WireGuard, Hubble relay disabled |

## Operator responsibilities

- Do not widen `default-deny.yaml`; add per-service policies instead.
- After a Cilium upgrade, verify Hubble flows are still visible in Grafana.
- Run `cilium connectivity test` after any node replacement.
