# data-dictionary

Every Postgres table column across all 18 eel services classified by ADR-0016 PII tier, retention period, encryption requirement, and data owner.

## Purpose in context

ADR-0016 requires that every column holding personal data is assigned a tier (A through E) and that the classification is auditable. This directory is the single source of truth. CI validates that every `eel-pii-*` typed column in every service's SQLAlchemy/sqlx/Ecto model has a matching entry here. The data dictionary also drives the audit shadow trigger generator in `eel-observability-*`.

## YAML format

```yaml
# bvr.yaml (example)
service: bvr
tables:
  voters:
    columns:
      national_id:
        tier: A
        type: PIIRestricted
        description: "National ID number"
        retention: "7 years post-election"
        encryption: column-level
        owner: "Registration Division"
      full_name:
        tier: B
        type: PIISensitive
        description: "Voter full name"
        retention: "7 years post-election"
        encryption: TDE
        owner: "Registration Division"
      polling_station_id:
        tier: D
        type: PIIOperational
        description: "Assigned polling station"
        retention: "3 years"
        encryption: at-rest
        owner: "Operations Division"
```

## Validate

```bash
# Check all classification files parse and conform to schema:
just validate-data-dictionary

# Check that all PIIRestricted/PIISensitive model columns have entries here:
just check-dictionary-coverage

# Generate a human-readable HTML report:
just generate-dictionary-report
```

## Adding a new table

1. Add the table entry to the relevant service YAML file
2. Run `just validate-data-dictionary`
3. Run `just check-dictionary-coverage` after adding the model columns
4. The audit shadow trigger for the new table is auto-generated by `eel-observability-*` on service startup

## Limitations

The data dictionary is a static YAML file; it does not auto-discover columns from live databases. CI enforces that all typed columns have entries, but the classification itself must be reviewed by the data protection officer before merge. Tier-A column-level encryption is a DBA responsibility and is not enforced by this tool.
