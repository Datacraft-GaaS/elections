# Platform JTBD Catalogue — eel

Integrated elections management platform (IEBC Kenya, tender IEBC/OIT/01/2026-2027).
This catalogue is the source of truth for platform-capability completeness: every job
users, admins, external actors, integrations, and system processes need to accomplish,
mapped to the workflow-system support that exists today, and the gaps that remain.

- **Entry point**: Catalogue + implement (Phase 1, then Phase 2)
- **Scope**: whole platform — 18 Kubernetes services, 69 functional modules, 43 shared packages, 40+ integrations. (User message scope field was empty; default scope = whole platform. Assumption recorded here.)
- **Date**: 2026-08-30
- **Stable IDs**: `JTBD-XXX` never renumber. Re-runs append IDs and update status/evidence in place.

## Status legend

| Status | Meaning |
|---|---|
| Live | Test suite passes, or deterministic structural signal (route registration, decorator, state-machine definition, migration) confirms it |
| Partial | Code exists but fails integration tests, or structure reveals missing transitions/gates/escalation |
| Planned | Documented in PRD/specs/tests; no implementation found via grep/AST |
| Implied | Absent in code and docs; logically required for data integrity or domain coherence |
| Strategic | Future ecosystem / long-term capability |
| Missing | Absent; no logical requirement or documentation found |

Evidence is labelled `runtime` (executed test: `path::test`) or `structural` (file:line, route, migration).
