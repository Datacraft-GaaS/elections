# OAG interface (M59)

Module M59 (`oag-interface`) owned by `governance-svc`. Provides the Office of the Auditor-General (OAG) with scoped, time-boxed read-only audit engagements: the OAG defines an `EvidenceScope` specifying which aggregates and time ranges it needs, the Commission legal officers approve the scope, and the system assembles a signed `EvidencePackage`. Scope creep is blocked by database-layer enforcement.

## 1. What the OAG Interface does (vs M54 Budget/Expenditure)

- **M54** = internal budget planning, procurement, and CoB reporting. It generates financial records.
- **M59** = controlled external disclosure of those records (and other the Commission evidence) to the OAG auditor, with scope and time-box limits that the OAG cannot bypass.

M59 does not produce new financial data; it packages existing records from M54, M63, M20, and other services into a signed export that the OAG can download and verify. the Commission retains control of what is disclosed and when.

## 2. Data plane

Three aggregates (per `services/governance-svc/crates/oag/src/models.rs` and the M59 spec):

| Aggregate | Purpose | Data class (ADR-0016) |
|---|---|---|
| **AuditEngagement** | Top-level OAG audit: `engagement_id`, `oag_ref_number`, `engagement_type` (ANNUAL / SPECIAL / FORENSIC), `scope_description`, `engagement_start`, `engagement_end`, `lead_auditor_name`, `status` (DRAFT_SCOPE / APPROVED / ACTIVE / CLOSED / CHALLENGED). | A |
| **EvidenceScope** | Approved disclosure boundary: `scope_id`, `engagement_id`, `included_modules` (array of M-numbers), `included_aggregates` (array of table names), `date_range_start`, `date_range_end`, `column_exclusions` (array of `table.column` pairs to redact), `approved_by` (the Commission legal officer), `approved_at`, commissioner HSM signature. | A |
| **EvidencePackage** | Assembled evidence export: `package_id`, `scope_id`, `generated_at`, `row_count`, `package_hash` (SHA-256 of the ZIP), `package_url` (MinIO path, time-limited presigned URL), commissioner HSM signature. | A |

## 3. Scope model and guard mechanisms

Every `EvidencePackage` is generated by a read query bounded to the approved `EvidenceScope`. Guards enforce this at multiple layers:

- **Application layer**: the query builder in `oag/src/assembler.rs` constructs SQL exclusively from the whitelisted `included_aggregates` and `date_range_*` fields; no raw SQL injection path exists.
- **Database layer**: a dedicated Postgres role `oag_read_role` has `SELECT` on only the tables and date-partitions named in the scope; the assembler connects as this role (not the application superuser). SpiceDB additionally enforces that the assembler process can only call the OAG assembly job for an `ACTIVE` engagement.
- **Column exclusion**: `column_exclusions` entries are translated into `NULL AS <column>` projections; the excluded columns (e.g., `payment_vouchers.payee_bank_account`) are never sent to the assembler query.
- **Time-box**: `AuditEngagement.engagement_end` triggers automatic revocation of the `oag_read_role` grants via a scheduled Postgres `REVOKE` job.
- **Scope change guard**: any modification to an approved `EvidenceScope` requires a new commissioner HSM signature and restarts the APPROVED state; the old package is invalidated.

## 4. Pipeline

Files on disk under `services/governance-svc/crates/oag/src`: `lib.rs`, `models.rs`, `engagement.rs`, `scope.rs`, `assembler.rs`, `routes/`.

```
OAG audit team notifies the Commission; legal officer creates AuditEngagement
      -> the Commission legal officer negotiates scope; creates EvidenceScope
      -> commissioner reviews + signs EvidenceScope with HSM
      -> emit eel.governance.oag_scope_approved.v1
      -> DB role grants activated for oag_read_role on approved tables
      -> OAG auditor (authenticated via OAG SVID) requests EvidencePackage
            -> assembler validates: engagement.status == ACTIVE
            -> assembler validates: current_time within date_range
            -> query executes as oag_read_role with column exclusions
            -> rows serialised to parquet (Apache Parquet via arrow2 crate)
            -> ZIP assembled; SHA-256 computed; signed by commissioner HSM
            -> uploaded to MinIO; presigned URL generated (48 h TTL)
            -> EvidencePackage row created; URL returned to OAG auditor
            -> emit eel.governance.evidence_package_delivered.v1
      -> engagement_end reached: DB role grants revoked automatically
      -> emit eel.governance.oag_engagement_closed.v1
```

## 7. Integrity + anti-tamper

- **HSM-signed scope**: every approved `EvidenceScope` carries a commissioner HSM signature; if the scope is altered post-approval the signature fails verification and the assembler refuses to proceed.
- **HSM-signed package**: every `EvidencePackage` carries a commissioner HSM signature over `SHA-256(package_id || scope_id || row_count || package_hash)`; the OAG auditor can verify the package was produced by the Commission and not modified in transit.
- **DB role grants as the enforcement mechanism**: even if the application-layer scope guard were bypassed (e.g., by a bug), the `oag_read_role` Postgres role cannot access tables outside the granted set.
- **Package URL TTL**: presigned MinIO URL expires after 48 hours; re-download requires a new package request, which is logged.
- **Scope change invalidation**: any approved `EvidenceScope` modification triggers automatic invalidation of all packages derived from it; OAG must request new packages.
- **Audit shadow**: every engagement and package event logged to `eel_governance_audit_shadow`.

## 8. Kenya statute alignment

- **Public Audit Act 2015 §35 (access to information)**: the OAG has statutory right to access the Commission financial records; `EvidenceScope` + `EvidencePackage` is the controlled mechanism for exercising that right.
- **Public Audit Act 2015 §36 (limitation on access)**: the Commission may limit OAG access to information that is the subject of a legal proceeding; the `column_exclusions` mechanism implements this without suppressing the row entirely.
- **Kenya Data Protection Act §26 (minimisation)**: personal data columns (voter IDs, staff national IDs) are excluded from OAG packages by default via `column_exclusions`; only financial aggregates and transaction IDs are disclosed.
- **Evidence Act Cap 80 §78 (electronic records)**: the HSM-signed package hash provides the authenticity anchor for admissibility of the OAG report as evidence.

## 9. Honest caveats + external prerequisites

- The OAG auditor SVID must be provisioned by the SPIFFE/SPIRE workload identity infrastructure; the OAG team must run a SPIRE agent or accept a short-lived SVID issued by the Commission's SPIRE server under a bilateral trust domain arrangement.
- Parquet serialisation is used for evidence packages because it is machine-readable and preserves column types; the OAG team needs Parquet tooling (e.g., Apache Drill, DuckDB, or Pandas) to inspect packages. A CSV fallback is available via a query parameter but loses type fidelity.
- The 48-hour presigned URL TTL may be too short if the OAG team is in a jurisdiction with slow download speeds; the TTL is configurable in `services/governance-svc/config/oag.toml`.
- Column exclusion covers only named columns; it does not prevent inference attacks (e.g., deriving a payee identity from cross-referencing transaction IDs with IFMIS public data). This is a known limitation documented to OAG as part of the scope approval process.

### Scope boundary example

For a typical annual audit engagement of election financial records:

| Field | Value |
|---|---|
| `included_modules` | `[M54, M63]` |
| `included_aggregates` | `["payment_vouchers", "procurement_records", "cob_reports", "serial_assignments"]` |
| `date_range_start` | `2027-01-01` |
| `date_range_end` | `2027-12-31` |
| `column_exclusions` | `["payment_vouchers.payee_bank_account", "staff_contracts.m_pesa_number"]` |

The assembler constructs:

```sql
SELECT
  id, procurement_id, payee_name, amount,
  NULL AS payee_bank_account,  -- excluded
  ifmis_transaction_id, recommended_by, approved_by, authorized_by
FROM payment_vouchers
WHERE created_at BETWEEN '2027-01-01' AND '2027-12-31'
-- Executed as oag_read_role; no access to tables outside scope
```

The OAG receives a Parquet file with the excluded column absent from the schema entirely, not as a NULL column, so the auditor cannot infer the number of values or their length.
