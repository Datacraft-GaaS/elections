# 5x Load Harness

Pre-production load validation at 5x the Appendix-A SLA targets. Confirms the platform sustains
peak election traffic without degradation before gate G6.

## Purpose

WP-6.4. Validates that each service meets its SLO from `loadtest/profiles/preprod-5x.yaml` under
sustained 5x load. Required for gate G6.

## Load targets (5x of Appendix-A)

| Service | 1x peak | 5x target | Key SLO |
|---------|---------|-----------|---------|
| rts-svc | 16 k events/s | 80 k events/s | p99 < 500 ms |
| bvr-svc | 5 k req/s | 25 k req/s | p99 < 1 s |
| abis-svc | 2 k probes/s | 10 k probes/s | p99 < 2 s |
| portal-svc | 500 k concurrent viewers | 2.5 M concurrent viewers | p99 < 3 s |
| bvi-svc | 3 k req/s | 15 k req/s | p99 < 500 ms |
| transparency-svc | 1 k writes/s | 5 k writes/s | p99 < 200 ms |

## Modes

### dry-mode

Validates k6 scripts, checks service health, and confirms Prometheus can scrape all targets. Runs
at 1% of 1x load for 60 s.

```bash
just load-5x dry
```

### live-mode

Runs full 5x load for 30 min sustained, then a 5-min burst at 6x for headroom validation.

```bash
just load-5x live ENV=preprod DURATION=30m
```

## Running a single service load test

```bash
k6 run --env SERVICE=rts-svc --env RATE=80000 \
  verification/load-5x/scripts/rts-submission.js
```

## Ramp profile

```
0-5 min:   ramp from 0 to 5x
5-30 min:  sustain 5x
30-35 min: burst to 6x
35-40 min: ramp down to 0
```

## Expected artefacts

Written to `verification/reports/load-5x-<date>/`:

- `k6-summary.json` -- k6 summary per scenario with percentile breakdown
- `hpa-events.json` -- HPA scale events during run
- `oom-events.json` -- any OOM kills observed
- `slo-compliance.json` -- per-service SLO pass/fail
- `gate-g6-load.sig` -- signed evidence for G6

## Pass criteria

- All p99 latencies below SLO thresholds for 95% of the sustain window
- Zero OOM kills in any tier-A service
- HPA scale-out completes within 45 s of threshold breach
- Kafka consumer lag recovers to below 5000 within 60 s of burst end
- No transparency log sequence gaps

## Dependencies

- `k6` >= 0.50 with xk6-kafka extension installed
- `loadtest/profiles/preprod-5x.yaml` present (generated by `just gen-load-profiles`)
- All services at minimum 2 replicas before run starts
- Prometheus retention >= 48 h for post-run analysis

## Limitations

- Requires dedicated pre-prod cluster: do not run against staging (shared with chaos-runner)
- Biometric probe load requires pre-generated `fixtures/biometric-probes.bin`
- Portal load test uses synthetic viewer sessions; real CDN behaviour not simulated
